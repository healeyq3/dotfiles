# dotfiles

My shell and git configuration for macOS (zsh) and Ubuntu (bash), kept under version control and symlinked into `$HOME` by `install.sh`.
The approach follows MIT's [Missing Semester](https://missing.csail.mit.edu/2026/command-line-environment/) dotfiles lecture.

## Structure

```
~/dotfiles/
├── install.sh        # symlinks configs into ~ (picks files per OS)
├── packages.sh       # installs packages (Homebrew on macOS, apt on Ubuntu)
├── Brewfile          # macOS packages
├── packages/
│   └── apt.txt       # Ubuntu packages
├── shell/            # shared by zsh and bash
│   ├── env           → ~/.shell_env    (PATH: uv, pixi; env vars)
│   └── aliases       → ~/.aliases      (eza aliases, code)
├── zsh/              # macOS only
│   ├── zshrc         → ~/.zshrc        (gitstatus prompt)
│   ├── zprofile      → ~/.zprofile     (Homebrew shellenv)
│   └── zshenv        → ~/.zshenv       (cargo env)
├── bash/             # Ubuntu only
│   └── bashrc        → ~/.bashrc       (Ubuntu defaults + gitstatus prompt)
└── git/
    ├── gitconfig     → ~/.gitconfig    (shared settings; includes ~/.gitconfig.local)
    └── ignore        → ~/.config/git/ignore   (global gitignore)

~/.gitconfig.local    # NOT in the repo: this machine's git name/email
```

Files in the repo have no leading dot so they're visible; `install.sh` maps each one to its real location.

## Setting up a new machine

```sh
# macOS only: install Homebrew first (https://brew.sh)

git clone <repo-url> ~/dotfiles
cd ~/dotfiles
./packages.sh     # Brewfile on macOS; apt + gitstatus on Ubuntu (uses sudo)
./install.sh      # symlink configs

# Git identity for this machine (personal or work), kept out of the repo
git config --file ~/.gitconfig.local user.name  "Your Name"
git config --file ~/.gitconfig.local user.email "you@example.com"
```

Open a new terminal tab to pick up the config.

On Ubuntu, `install.sh` replaces any existing `~/.bashrc`. The old one is saved in `~/.dotfiles_backup/<timestamp>/`, so check it for anything worth keeping, such as a `conda init` block.

## macOS vs Ubuntu

| | macOS | Ubuntu |
|---|---|---|
| Shell | zsh (`zsh/`) | bash (`bash/`) |
| Packages | `Brewfile` via `brew bundle` | `packages/apt.txt` via apt |
| gitstatus | `brew install romkatv/gitstatus/gitstatus` | cloned to `~/.local/share/gitstatus` |

- **Shared config:** anything that should work in both shells goes in `shell/env` (PATH, env vars) or `shell/aliases`. Those files must stay valid in both bash and zsh, so use `[ ]` rather than `[[ ]]` and no zsh-only syntax.
- **OS-specific config:** use a `case "$(uname -s)" in Darwin) ... ;; Linux) ... ;; esac` block, as in `shell/aliases`.
- **Ubuntu bashrc:** `bash/bashrc` first sources Ubuntu's stock `/etc/skel/.bashrc` (history, completion, colors) and then layers our aliases and prompt on top.
- **Prompt:** both shells show the same prompt: `user@host dir  branch ↓↑~+!? ❯`. The branch symbol needs a Nerd Font in your terminal. When you SSH into Ubuntu from the Mac, the Mac terminal's font is what matters.

## Packages

**macOS:** `Brewfile` is generated by Homebrew. After installing or removing something:
```sh
brew bundle dump --force --file=~/dotfiles/Brewfile   # update the Brewfile
brew bundle check --file=~/dotfiles/Brewfile          # anything missing/outdated?
brew bundle cleanup --file=~/dotfiles/Brewfile        # list installed things NOT in the Brewfile (--force to remove)
```

**Ubuntu:** edit `packages/apt.txt` by hand, with one package per line and `#` for comments. If a package doesn't exist in the current Ubuntu release, `packages.sh` skips it and prints a note. For example, `eza` is only in apt on Ubuntu 24.04+; on older releases, see eza's [install instructions](https://github.com/eza-community/eza/blob/main/INSTALL.md).

When adding a package that both systems use, add it to both lists. Package names sometimes differ, such as `poppler` (brew) vs `poppler-utils` (apt).

## How `install.sh` works

It builds a list of `"repo/path:path-in-HOME"` links: the shared ones plus the ones for the current OS. For each link, it:

- does nothing if the correct symlink is already in place (`ok`),
- otherwise moves any existing file at the target to `~/.dotfiles_backup/<timestamp>/` (`backup`),
- then creates the symlink (`linked`).

It's safe to re-run at any time.

## Git identity

The shared `git/gitconfig` holds no personal info. It ends with
`[include] path = ~/.gitconfig.local`, and that untracked file holds the identity for each machine.
My personal Mac has my personal identity there, and my work machine has my work identity.

Because `~/.gitconfig` is a symlink into this repo, **`git config --global ...` writes into the repo**.
Use `git config --file ~/.gitconfig.local ...` for anything machine-specific or private.

## Day-to-day use

- **Editing:** edit `~/.zshrc` (or the file in the repo, which is the same file), then commit from `~/dotfiles`.
- **Adding a new config file:**
  1. Copy it into the repo, without the leading dot, e.g. `cp ~/.vimrc vim/vimrc`.
  2. Add a line to `links` in `install.sh`. Use the shared list, or the `Darwin`/`Linux` list if it's OS-specific.
  3. Run `./install.sh`. It backs up the original and links in the repo copy.
  4. Commit.
- **Removing a file:** delete its line from `install.sh`, then replace the symlink with a real copy:
  `cp ~/dotfiles/foo/foorc /tmp/foorc && rm ~/.foorc && mv /tmp/foorc ~/.foorc`.
- **Installers that edit rc files:** installers like rustup, uv, conda, and nvm append lines to `~/.bashrc` or `~/.zshrc`. Those files are symlinks, so the changes land in the repo. Check `git diff`, and either keep a cleaned-up, guarded version or revert it.

## Portability

Lines that source tool-specific files (uv, cargo, gitstatus) check that the file exists first, so a fresh machine without those tools starts a shell without errors.
Follow the same pattern for anything machine-specific: `[ -f path ] && . path`.

## Notes

- Don't commit secrets or identifying info, such as git name/email, tokens, private keys, or a `~/.ssh/config` with real hosts.
  Put them in untracked `*.local` files that the tracked config includes or sources.
