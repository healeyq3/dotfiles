# CLAUDE.md

Personal dotfiles repo for macOS (zsh) and Ubuntu (bash). Config files live here and are symlinked into `$HOME` by `install.sh`. See README.md for the full how-to.

## Layout

- `install.sh`: bash script that builds a `links=(...)` array of `"repo/path:path-relative-to-HOME"` pairs. Shared links come first, then the links for the current OS go in a `case "$(uname -s)"` block (`Darwin` or `Linux`). It backs up existing targets to `~/.dotfiles_backup/<timestamp>/`, then symlinks them. It is idempotent.
- `packages.sh`: on macOS it runs `brew bundle --file=Brewfile`. On Ubuntu it runs `apt-get install` for the entries in `packages/apt.txt`, skipping any the release doesn't have, and clones or updates gitstatus in `~/.local/share/gitstatus`.
- `Brewfile`: generated by `brew bundle dump --force --file=Brewfile`. Regenerate it rather than hand-editing where possible.
- `packages/apt.txt`: one package per line, `#` comments. Mirrors the Brewfile where an apt equivalent exists.
- `shell/env` → `~/.shell_env` and `shell/aliases` → `~/.aliases`: sourced by both the zshrc and the bashrc. They must be valid in both bash and zsh: use `[ ]`, POSIX-ish syntax, and no zsh-only features.
- `zsh/zshrc`, `zsh/zprofile`, `zsh/zshenv`: macOS only. The zshrc has the gitstatus prompt (`my_git_prompt` precmd hook, gitstatus from Homebrew).
- `bash/bashrc` → `~/.bashrc`: Ubuntu only. It sources `/etc/skel/.bashrc` for the Ubuntu defaults, then `~/.aliases`, then sets up a gitstatus prompt (`my_prompt` via `PROMPT_COMMAND`) that mirrors the zsh prompt. Keep the two prompts visually in sync.
- `git/gitconfig` → `~/.gitconfig`: shared settings only, ending with `[include] path = ~/.gitconfig.local`.
- `git/ignore` → `~/.config/git/ignore`.
- `~/.gitconfig.local` is untracked and holds each machine's git identity. The personal Mac uses the personal identity, and a separate work machine uses the work identity.

## Conventions

- Repo filenames have no leading dot; the target path in `install.sh` adds it.
- When adding a config file, copy it into the repo, add a `links` entry (shared or OS-specific), and run `./install.sh`. Keep README.md's structure tree in sync.
- When adding a package, add it to both `Brewfile` and `packages/apt.txt` if it's wanted on both. Names can differ (e.g. `poppler` vs `poppler-utils`).
- The files in `~` are symlinks into this repo, so editing `~/.zshrc` edits the repo file directly.
- Guard sourcing of tool-specific files with an existence check (`[ -f path ] && . path`) so the config works on machines without that tool.
- Gate OS-specific settings with `case "$(uname -s)"`.
- `install.sh` and `packages.sh` must stay compatible with macOS's bash 3.2: no associative arrays, no `readlink -f`, no `mapfile`. `bash/bashrc` only runs on Ubuntu (bash 5), and gitstatus requires bash 4+.
- The bashrc prompt disables `promptvars` and escapes backslashes in branch and directory names. The zshrc relies on `no_prompt_subst` and escapes `%`. Don't remove either; they stop branch or directory names from injecting code into the prompt.
- After editing, check syntax: `zsh -n zsh/zshrc`, `bash -n bash/bashrc install.sh packages.sh`.
- Never commit secrets or identity (git name/email, tokens, keys, SSH host details). Put them in untracked `*.local` files.
- Never run `git config --global` for identity, because `~/.gitconfig` is a symlink into this repo. Use `git config --file ~/.gitconfig.local`.
- Keep the `[include]` of `~/.gitconfig.local` at the end of `git/gitconfig` so local values win.
- gitstatus comes from the `romkatv/gitstatus` tap, not homebrew-core: `brew install romkatv/gitstatus/gitstatus`.
